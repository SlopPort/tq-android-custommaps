# Optional Perf launch through the manager

The manager now stores a separate Perf preference and freezes it into each startup
request. Vanilla selection can therefore retain Perf while using the ordinary
database and save paths. The launch switch affects the next process. Individual
patch controls remain in the existing Perf overlay.

The local build includes a trusted copy of the previously installed Perf runtime
and its Traders add-on. The public embedding tool accepts that script as an
explicit local input; no game or module binary is redistributed here.

Local APK SHA-256: `abc014c1c4918b871f53404b419c4aa9c9d2c718c93b8a5b75d1e0f68d69278b`.
A fresh backup containing 7,199 entries was captured before installation.
In process 10517, the current-process report showed all seven requested engine
patches and the overlay active; Traders initialized 2,946 items. The Perf menu
opened visibly at the main menu. This confirms initialization, not a new FPS
benchmark or complete gameplay regression test. A separate launch in process 12992 reported Perf off after disabling the switch.
The final stored choices are Perf on and vanilla selected. The old root injector remains
paused to avoid duplicate installation.

The original pin-shortcut icon used a framework resource which this launcher
rejected. A bitmap icon fixed the native pin request. The manager activity was
also placed directly on the primary Home screen as **Titan Quest Mods**, and
opening that icon returned to the manager. The launcher service additionally
reports the requested **TQ Mods + Perf** shortcut pinned; its separate Home-screen
placement was not relied on.

Java compilation and all 13 JavaScript test files passed. The orchestration mock
checks the optional Perf callback; actual launch was checked with the locally
bundled module on the rooted test phone. Google Play and stock-phone setup remain
unverified. The map movement defect and the wider release checklist remain open.
