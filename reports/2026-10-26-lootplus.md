# LootPlus 1.3: initial Android staging test

Date: 2026-10-26

## Environment

Titan Quest Ultimate 3.0.5339 (30005339), arm64, rooted Redmi Note 8. Existing Perf and Traders modules were left in place. No campaign character was intentionally loaded for this test. A local backup of SaveData was made before staging.

## Source and specimen

The mod author's [forum post](https://titanquestfans.net/index.php?topic=934.0) links to a [download index](https://pastebin.com/KyhsHRNZ), which provides LootPlus v1.3 non-Workshop (no 2x):

[Author-linked LootPlus 1.3 download](https://mega.nz/file/gi5GCKDB#CaHmwCe1Oew3xpNuRwdwttai2YZSCWXUw2vU8gDZi7w)

Downloaded filename: `lootplus-Bounce v1.3.zip`; 4,026,362 bytes.
SHA-256: `54f0170783f517bc9c84492f3259f0588a3df9639fba37aa15b0f13ccc95f7b2`.

The included instructions require Custom Game selection, then a bounce back to character selection. This is a database/bounce test, not a playable custom terrain-map test.

## Staging

Copied the original directory structure to:

`/sdcard/Android/data/com.hg.titanquestultimate/files/Preferences/CustomMaps/lootplus/`

The directory did not previously exist. Three files were copied (6,077,360 bytes in total). Device SHA-256 values:

The 164-byte map begins with `MAP` and byte `06`. This observation alone does not establish engine acceptance or compatibility.

## Results so far

- Filesystem staging: completed.
- Main menu before staging: no visible Custom Game entry.
- Post-staging restart: the main menu was observed again; no Custom Game button was visible.
- Character-selection screen: observed and inspected; no custom-map selector was visible in the observed view.
- Engine discovery: not measured.
- Activation / modified loot / custom gameplay / save-reload: not tested.

The downloaded folder uses lowercase `resources/`, whereas the retained discovery code references `/Resources/`. An ADB shell listing of the staged uppercase `Resources/` path succeeded and returned `Maps` and `Maps.arc`. This rules out a missing directory under that spelling for this shell check; it does not prove engine-level discovery.

Correction: the earlier report that ADB taps failed to reach character selection was unsupported. The user reported already being on that screen, and a subsequent screenshot confirmed it. The cause of the earlier screenshot discrepancy is unknown. No campaign launch was intentionally requested during this follow-up.

## Static caveats

The retained discovery code is not sufficient evidence that the mobile UI invokes it. The reviewed GameInfo::GetModName(bool) decompilation constructs an empty string, an additional obstacle requiring instruction-level and runtime verification. Map-version checks vary by call mode; passing a header check would not prove successful loading.

## Reversal

The test added only the `CustomMaps/lootplus` directory to external game storage. Remove or move that exact directory while the game is closed to undo staging. Do not delete the parent Preferences or SaveData directories.
